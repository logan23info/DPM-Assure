# Audit Methodology

DPM-Assure follows a controlled assurance lifecycle.

## Lifecycle

`SOURCE → REQUIREMENT → CONTROL → ORGANIZATION → ENGAGEMENT → INDEPENDENCE/CONFLICT CHECK → RISK ASSESSMENT → AUDIT PLAN → FRAMEWORK/SCOPE → APPLICABILITY → SAMPLING → WORKPAPER → PROCEDURE → PBC/CLIENT REQUEST → EVIDENCE → AI ASSISTANCE → EVIDENCE GATE → TEST → EXCEPTION → FINDING → RISK → REMEDIATION/RISK ACCEPTANCE → RETEST → REVIEW/QA → SIGN-OFF → REPORT → AUDIT FREEZE → ARCHIVE → CONTINUOUS MONITORING → CHANGE/NEW EVIDENCE → REASSESSMENT`

## Independence

An engagement must pass independence and conflict checks before assurance work proceeds. Conflicts are explicit workflow records and cannot be bypassed by UI state.

## Risk assessment

Preliminary risk assessment informs audit planning, scope, procedures, sampling, and review depth. Risk scoring is deterministic and explainable.

## Workpapers

Workpapers contain purpose, scope, procedure, population/sample information, evidence references, test steps, results, exceptions, conclusion, preparer, reviewer, and version history.

## Evidence Gate

Before a test conclusion can be accepted, required evidence must be present, attributable, integrity-checked, applicable to the control/procedure, and within the required temporal scope. Failure is explicit.

## Findings

The methodology distinguishes observation, exception, finding, risk, remediation, and risk acceptance. Closure requires evidence of remediation or a controlled risk-acceptance decision.

## Review and sign-off

Prepared work is independently reviewed. Sign-off is a human authorization event. AI cannot autonomously approve a conclusion.

## Freeze

After sign-off/report finalization, the engagement is frozen. Corrections use controlled versions or superseding records; prior history remains preserved.
