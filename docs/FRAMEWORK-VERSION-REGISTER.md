# Framework Version Register

Frameworks are governed objects, not free-form labels.

Each framework version must record:

- framework identifier and name
- issuing authority
- edition/version
- jurisdiction and applicability
- publication date
- effective date
- retirement/withdrawal date when applicable
- status (`DRAFT`, `CURRENT`, `SUPERSEDED`, `RETIRED`)
- canonical source URL
- validation date and validator
- review cadence
- licensing/copyright notes

## Version rules

1. Never silently replace a framework version.
2. Historical engagements retain the framework version used at the time.
3. A new edition is a new governed version.
4. Applicability is evaluated for the engagement; it is not assumed from framework presence.
5. Mappings between versions must identify their provenance and rationale.

## Initial research candidates

The initial registry will evaluate, among others, NIST Privacy Framework, ISO/IEC 27701, ISO/IEC 27001, ISO/IEC 27018, AICPA Trust Services Criteria, OWASP ASVS, CSA CCM, ISO/IEC 29134, ISO/IEC 29184, IIA Global Internal Audit Standards, GDPR materials, India's DPDP Act/Rules, and applicable state or sector requirements.

Research status must be recorded before any item becomes authoritative product content.
